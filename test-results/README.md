# ผลทดสอบ TC-34 ขึ้นไป (ดิบ ยังไม่ใช่ตารางสุดท้าย)

ทดสอบเมื่อ 2026-10-28 บน iOS Simulator (iPhone 16 Pro, iOS 18.3) ต่อกับ backend รันในเครื่อง (`localhost:3000`) ซึ่งใช้ฐานข้อมูล Supabase จริงตาม `backend-api/.env`
ข้อมูลทดสอบใช้บัญชี/ทริปที่ขึ้นต้น `tc34_` / `TC34` และลบออกจากฐานข้อมูลแล้วหลังทดสอบ

## วิธีทดสอบสองแบบ (ต้องระบุในเล่มให้ถูก)
- **API** (`tc34-api-tests.mjs`, ผลดิบใน `tc34-api-results.json`): เรียก endpoint จริงและตรวจค่าที่ตอบกลับ/ข้อมูลในฐานข้อมูล
- **UI** (`native-ios/GoWithUsUITests/TC34Tests.swift`, ภาพใน `screenshots/`, บันทึกใน `ui-observations.txt`): ควบคุมแอปบน Simulator
  - XCUITest พิมพ์ช่องรหัสผ่านของแอปไม่เสถียร จึงใช้ตัวช่วยชั่วคราวเติมอีเมล/รหัสผ่านจาก launch argument (patch: `tc34-temp-app-hooks.patch`, ลบออกจากแอปแล้ว) แล้วเทสต์กดปุ่ม "เข้าสู่ระบบ"/"สมัครสมาชิก" จริง ภาพ `login-*-prefilled.png`, `register-form-prefilled.png` แสดงฟอร์มที่เติมไว้
  - ถ้าจะรันซ้ำ ต้อง `git apply test-results/tc34-temp-app-hooks.patch` ก่อน (patch นี้ยังแก้ `baseURL` ให้ชี้ localhost ด้วย) แล้วรัน `tc34-watcher.mjs` ค้างไว้ (ใช้ใน TC-36, TC-40)

## Postman IT-06 (เข้าร่วมทริป) 0/1
- สาเหตุที่ reproduce ได้: ส่งคำขอเข้าร่วมซ้ำ (ผู้ใช้เป็นสมาชิกอยู่แล้ว) ได้ 200 "Participant updated successfully" แต่ assertion ต้องการ 201 → 0/1 (ไม่เห็นการรันเดิมของภาพ 3.68 จึงยืนยันไม่ได้ว่าเป็นสาเหตุเดียวกับที่เจอ)
- แก้: เพิ่ม pre-request script ใน `backend-api/Go_With_Us_Integration.postman_collection.json` ให้ออกจากทริปก่อน (ไม่แก้ API) รัน newman 3 รอบได้ 1/1
- พบเพิ่ม ยังไม่ได้แก้: IT-02 คาดหวัง 201 "User registered successfully" แต่ API ตอบ 202 (ต้องยืนยัน OTP) · IT-05 ล้มเหลวเพราะทริปในคอลเลกชันใช้วันที่ 2026-09-20 ซึ่งผ่านมาแล้ว
