# ฟีเจอร์แอดมิน (Admin Features) - คู่มือการควบคุมและดูแลระบบ

เอกสารฉบับนี้จัดทำขึ้นเพื่ออธิบายและเป็นคู่มือสำหรับแอดมินในการใช้งานฟีเจอร์ต่างๆ ภายในแพลตฟอร์ม GoWithUs

## 1. ภาพรวม (Overview)
แพลตฟอร์มนี้มีระบบการจัดการสำหรับแอดมิน เพื่อดูแลความปลอดภัยและความเรียบร้อยของชุมชนผู้ใช้งาน โดยมาพร้อม 2 ฟีเจอร์หลักในการดูแลระบบดังนี้:
1. การตรวจสอบและยืนยันตัวตนผู้ใช้บริการ (Identity Verification)
2. การจัดการรายงานพฤติกรรมผู้ใช้และการระงับบัญชี (User Reports & Banning)

## 2. การตั้งค่าผู้ใช้งานให้เป็นแอดมิน (Setting Up an Admin)
โดยค่าเริ่มต้น ผู้ใช้งานใหม่ที่สมัครเข้ามาทุกคนจะได้รับสถานะเป็น `user` หากคุณต้องการเปลี่ยนผู้ใช้งานให้มีสิทธิ์เป็นแอดมิน (ให้สามารถเข้าถึง Dashboard ด้านล่างได้) สามารถทำตามขั้นตอนต่อไปนี้:

1. เชื่อมต่อเข้าฐานข้อมูล (Database) ด้วย Prisma Studio หรือโปรแกรมอื่นๆ (เช่น DBeaver / TablePlus):
   ```bash
   cd go-with-us-backend
   npx prisma studio
   ```
2. ไปที่ตาราง `User`
3. ค้นหาแถวของผู้ใช้ที่คุณต้องการ และเปลี่ยนช่อง `role` จาก `user` เป็น `admin`
4. กดบันทึกการเปลี่ยนแปลง (Save)
5. กลับมาที่เว็บแอป ออกจากระบบ (Logout) และล็อกอินเข้ามาใหม่อีกครั้งเพื่อรับสิทธิ์แอดมิน

## 3. วิธีการเข้าสู่แดชบอร์ดจัดการระบบ (Accessing the Dashboard)
- แผงควบคุมระบบจัดทำอยู่บน **หน้าเว็บ (Web App)**: ให้ล็อกอินด้วยอีเมลของแอดมิน จากนั้นคลิกที่ไอคอนโปรไฟล์ (Avatar) บนแทบเมนูด้านบนขวา (Navbar) เพื่อเปิดเมนูการตั้งค่าขึ้นมา
- หากต้องการดูและจัดการเรื่องการยืนยันตัวตน ให้กดไปที่เมนู **"ตรวจสอบยืนยันตัวตน (Admin)"** ระบบจะนำคุณไปยังหน้า `/admin/verify`
- หากต้องการดูคนโดนรายงานและเรื่องการแบน ให้กดไปที่เมนู **"จัดการรายงาน (Admin)"** ระบบจะนำคุณไปยังหน้า `/admin/reports` *(รายการเหล่านี้จะมองเห็นได้เฉพาะคนที่ถูกเซ็ตให้เป็น admin ในระบบเท่านั้น)*

## 4. ระบบตรวจสอบและยืนยันตัวตน (Identity Verification)
- หลังจากผู้ใช้ส่งคำขอเข้ามายืนยันตัวตนที่ฝั่งแอป/เว็บ สถานะของบัญชีเขาจะเปลี่ยนเป็น **"รอตรวจสอบข้อมูล" (Pending)**
- พอแอดมินเปิดเข้ามายังเมนู **ตรวจสอบยืนยันตัวตน (`/admin/verify`)** หน้าจอจะโหลดรายการที่ยังไม่ได้รับอนุญาตทั้งหมด โดยจัดเรียงรายการที่ส่งมาล่าสุดไว้บนสุด
- สำหรับแต่ละคำขอ แอดมินจะสามารถเทียบรูปถ่าย **"บัตรประชาชน / Passport"** ที่ผู้ใช้อัปโหลดมา ควบคู่ไปกับป้ายด้านขวาคือรูป **"ใบหน้าแบบเซลฟี่ (Face Scan)"** ได้เลย
- หากข้อมูลใบหน้าตรงกันและสามารถระบุตัวตนได้ชัดเจน: แอดมินสามารถกดปุ่มสีเขียว **"ยืนยัน (ข้อมูลตรงกัน)"** ได้ทันที (หลังกด ระบบจะเพิ่มป้ายเขียว Verified (🟢) ลงในโปรไฟล์ของผู้ใช้ แจ้งว่ายืนยันตัวตนผ่านแล้ว)
- หากรูปเบลอ หรือข้อมูลภาพไม่ตรงกันให้แอดมินกดปุ่มสีแดง **"ปฏิเสธ (รูปไม่ชัดเจน)"** (หลังกด ระบบจะลบรูปที่ผู้ใช้อัปโหลดมาทิ้ง และผู้ใช้ต้องส่งรูปเข้ามาขอสถานะใหม่อีกครั้ง)

## 5. การระงับบัญชีผู้ใช้งาน (Banning Users)
- แอดมินสามารถเข้ามาดูข้อมูลรายงานที่มีคนแจ้งเข้ามาได้ที่เมนู **จัดการรายงาน (`/admin/reports`)** รายการรายงานจะถูกนำมาเรียงจากข่าวล่าสุดเช่นกัน
- แอดมินสามารถอ่านสาเหตุที่รายงาน ดูว่าใครเป็นคนแจ้ง (Reporter) และใครคือคนที่ถูกแจ้ง (Reported)
- ถ้าแอดมินตัดสินว่าคนนั้นผิดจริง สามารถกดปุ่ม **"แบนผู้ใช้" (Ban)** ผู้เล่นคนนั้นจะถูกบล็อกจากระบบทันที ไม่สามารถเข้าสู่ระบบแอป หรือส่งคำขอ API ได้อีก (ตามเงื่อนไขที่เซ็ตไว้ใน Middleware `auth.js`)
- หากแอดมินลบล็อก หรือพบว่ารายงานนั้นไม่เป็นความจริง สามารถกดเข้าไปในหน้านี้อีกรอบแล้วกดปุ่มสลับให้กลับมาเป็น **"ปลดแบน" (Unban)** ผู้ใช้งานก็สามารถเข้าแอปได้ปกติครับ

## ข้อมูลเชิงเทคนิค (Technical Details)
- **Backend Routes** (เส้นทางของ API):
  - `POST /api/users/verify/request` - สร้างคำขอยืนยันตัวตนใหม่ (เข้าถึงได้โดย `user` ทั่วไป)
  - `POST /api/users/verify/:targetId` - กดตอบรับอนุมัติ/ปฏิเสธสถานะ (เข้าถึงได้เฉพาะ `admin`)
  - `GET /api/users/verify/requests` - ดึงข้อมูลคำขอยืนยันตัวตนที่ค้างอยู่ (เข้าถึงได้เฉพาะ `admin`)
  - `POST /api/users/:targetId/report` - สร้างรายงานเหตุแบนผู้ใช้ (เข้าถึงได้โดย `user` ทั่วไป)
  - `POST /api/users/:targetId/ban` - กดแบน/ปลดแบน ผู้ใช้งานในระบบ (เข้าถึงได้เฉพาะ `admin`)
  - `GET /api/users/reports/all` - ดึงรายละเอียดการรายงานทั้งหมดมาแสดง (เข้าถึงได้เฉพาะ `admin`)

## ข้อควรระวังเรื่องความมั่นคงปลอดภัย (Security Notes)
- การกระทำต่างๆ ที่ระบุไว้ด้านบน จะต้องให้แอดมินส่งคำขอด้วย JWT token ที่มีสิทธิ์ผูกกับ Role ของแอดมินจริงๆ เท่านั้น
- เพื่อประสิทธิภาพและความปลอดภัยขั้นสูง ในระดับการสั่งการ Backend จะมีการยืนยันความถูกต้องด้วยคำสั่งเช็กเสมอว่าผู้ขอนั้นถือบัตรที่มีบทบาทบรรทัดที่บอกว่า `role === 'admin'` อยู่หรือไม่ ก่อนที่จะยอมอัปเดตสถานะให้ผู้มีสิทธิครับ
