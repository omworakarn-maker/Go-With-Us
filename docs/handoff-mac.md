- กฎการแก้เล่ม:
  - ใช้ officecli
  - ทุกรอบบันทึกเป็นเลขถัดไป (55, 56, …) ไม่บันทึกทับ และไม่ต้องทำ backup
  - ห้ามกด Update Field ที่สารบัญ ให้เขียนเลขหน้าเอง
  - คงรูปแบบเดิมของเล่มไว้
  - อ้างอิงแบบ IEEE ตอนนี้มี 46 รายการ และถูกอ้างในเนื้อหาครบทุกรายการ
- ข้อมูลประเมิน:
  - หัวข้อ 4.6: ผู้ทดลองใช้งาน 20 คน ใส่ผลแล้ว ภาพรวม x̄ = 3.98, S.D. = 0.45
  - หัวข้อ 4.7: ผู้เชี่ยวชาญ ยังรอข้อมูล
  - SUS ตัดออกจากเล่มแล้ว
  - **ห้ามแต่งผลทดสอบหรือผลประเมินขึ้นเอง**
- แผนการทดสอบ:
  - บท 3 ตารางที่ 3.13: TC-01 ถึง TC-33 แบ่ง 7 กลุ่ม
  - บท 4 ตาราง 4.1–4.7: แสดงผลตามรหัสเดียวกัน ทุกกรณีผ่านแล้ว

## งานที่จะทำบน Mac (ทดสอบบน iOS Simulator)
1. รัน Backend (`backend-api`, ต้องมีไฟล์ `.env` ซึ่ง copy มาจากเครื่อง Windows หรือจากเจ้าของโปรเจกต์) และ build แอป iOS เปิดบน Simulator
2. ทดสอบกรณีเพิ่ม แล้วบันทึกผลจริง (ผ่าน/ไม่ผ่าน) พร้อมภาพหน้าจอ เพื่อเพิ่มเป็น TC-34 ขึ้นไป:
   - ผู้ใช้ไม่ได้ตอบความชอบบางข้อ ระบบเฉลี่ย Match Score เฉพาะด้านที่มีข้อมูล
   - ทริปที่สิ้นสุดแล้วไม่แสดงในรายการแนะนำ
   - กรอกรหัส OTP ผิด และกรอกรหัสที่หมดอายุ
   - สมัครด้วยอีเมลที่มีในระบบแล้ว
   - เข้าร่วมทริปเดิมซ้ำ
   - ผู้ใช้อื่นพยายามแก้ไขหรือลบทริปที่ตนไม่ได้สร้าง
   - ปิดอินเทอร์เน็ตระหว่างใช้งาน
3. Postman เข้าร่วมทริป (ภาพ 3.68) เดิมได้ Test Results 0/1 ให้หาสาเหตุใน assertion แล้วรันใหม่ให้ได้ 1/1
4. ย่อหน้าท้ายหัวข้อ 4.4: การนับสมาชิกสถานะ "สนใจ" กับ "เข้าร่วม" ไม่ตรงกัน ให้ตรวจโค้ดว่าควรแก้หรือไม่
5. เก็บผลและภาพทั้งหมดไว้ในโฟลเดอร์ `test-results/` แล้วนำกลับไปแก้เล่มบนเครื่อง Windows
